# Python 与命令执行规则

本文是 [SKILL.md](SKILL.md) 的中文翻译，便于阅读和对照。

适用范围：编写、修改、重构、审查、调试或补全 Python 代码、脚本、自动化流程、命令执行辅助程序，以及执行 Shell 或系统命令时，必须遵守本技能规定的 Python 优先、命令执行、结构化结果、错误处理和代码质量规则。

处理上述任务时，应用下列所有相关规则。改动应限于用户请求的范围，并遵守已有授权边界。

详细示例按本文的主要章节分类存放在 `references/` 中。编写或审查相关模式前，只阅读对应的参考文件。

## 工作流程

1. 开始操作前，阅读仓库说明，检查受影响的代码、可用的 Python 解释器、目标运行环境和相关检查配置。

2. 确定任务涉及的规则章节，并阅读对应示例。涉及 Vue、TypeScript 或样式时，同时应用 `vue-code-rules`、`ts-code-rules` 或 `css-code-rules`。Python 是自动化任务的首选语言，不应因此替换项目本身的实现语言。

3. 文件操作和自动化优先使用 Python 标准库。确需外部工具时，通过 Python 的 `subprocess` 模块调用。

4. 检查最终改动并执行有针对性的验证。对于命令执行辅助程序，需要验证成功执行及相关失败路径。无法执行的检查应明确说明，不能暗示其已通过。

## 语言与工具选择

选择 Python 启动方式、调用外部工具或处理命令结果时，阅读[命令执行示例](references/command-execution-examples.md)。

1. 脚本、自动化、文件处理和命令编排优先使用 Python。Python 能完成的操作，应避免使用 PowerShell、Batch 或 Shell 脚本。

2. 文件操作使用 `pathlib` 和标准库 API。Git、rg、构建工具及其他必要的系统命令通过 `subprocess` 执行。

3. 如果执行工具只接受 Shell 命令字符串，Shell 仅用于启动 Python。简单操作使用 `python -c`；复杂、多行或可复用的逻辑放入 `.py` 脚本。不要将不可信文本插入 Shell 字符串或 Python 源码。

4. 仅当 Python 不可用，或确实需要 Shell 专属能力时，使用必要的替代方式，并简要解释原因。不要为此安装无关运行环境或绕过权限。

## 命令执行与结果

实现子进程调用、UTF-8 处理、超时或结构化失败结果前，阅读[命令执行示例](references/command-execution-examples.md)。

1. 优先使用 `subprocess.run`，参数采用列表，设置 `shell=False`。通过 `cwd` 指定工作目录，使用 `pathlib.Path` 构造路径，不要拼接依赖平台的路径字符串。

2. 设置 `capture_output=True`、`text=True` 和 `encoding="utf-8"`，同时捕获标准输出和标准错误。工具确实使用其他编码时，应明确适配，不能静默损坏输出。最终输出端也必须支持 UTF-8，包括 Windows 控制台和 JSON 输出。

3. 检查返回码，设置合理的超时，并处理 `OSError` 和 `subprocess.TimeoutExpired`。使用 `check=True` 时，还必须处理 `subprocess.CalledProcessError`。

4. 成功、非零退出、启动失败和超时都必须返回相同的结构化字段。保留已有输出和有用的错误上下文，不得吞掉失败或只打印成功消息。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `success` | `bool` | 仅当命令执行完毕且退出码为零时为 True |
| `return_code` | `int \| None` | 实际退出码；无法取得退出码时为 `None` |
| `output` | `str` | 捕获的标准输出，包括可获取的部分输出 |
| `errors` | `str` | 捕获的标准错误及必要的异常上下文 |

5. 标准错误中有内容，并不代表执行失败。应根据命令是否完成及其返回码判断成功与否。启动当前 Python 解释器时使用 `sys.executable`。

## 代码质量与文件处理

组织脚本、处理文件、命名 Python 符号或定义可执行入口时，阅读[代码质量示例](references/code-quality-examples.md)。

1. 使用职责清楚的函数和类组织代码，提供适当的类型标注和文档。仅因真实复用、复杂度或职责边界而提取抽象。

2. 变量和函数使用 `snake_case`，类使用 `UpperCamelCase`。这些命名规则适用于 Python 辅助程序；项目语言代码遵守其对应技能。

3. 在负责报告或恢复的层级处理文件操作、命令执行和外部调用错误。捕获相关异常，保留有用上下文，避免空异常处理。

4. 可执行脚本使用 `main()` 入口和 `if __name__ == "__main__":` 保护。导入可复用模块时，不得自动启动任务。

5. 保持代码易读，不保留无用调试输出。遵循支持的 Python 版本；跨平台辅助程序中不要固定盘符、硬编码解释器路径或使用只能在 Shell 中运行的语法。
