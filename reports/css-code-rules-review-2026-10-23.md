## 确认问题

### F1 · P2：省略号示例缺少生效所需的布局条件

位置：[dom-nesting-examples.md](../css-code-rules/references/dom-nesting-examples.md)，第 164–185 行；关联 DOM 在第 18–24 行。

Scenario 4 明确复用 Scenario 1 的标题和摘要，但两个目标都是普通 `span`。给出的 mixin 只有 `overflow: hidden`、`text-overflow: ellipsis`、`white-space: nowrap`；示例未提供改变其内联布局的声明，也未说明可用宽度约束。

在所给 DOM 和样式下，普通非替换内联元素不能靠这三个声明形成预期的单行截断区域；长文本不会按示例所称产生省略号。这个问题来自元素格式化上下文，并非 Less 的 mixin 语法。

**建议：**补全一个可以独立复现截断的正例：让消费者成为具有受约束可用宽度的块容器，或明确交代既有布局已经提供这些条件。如果是 Flex 项，还应按实际收缩链判断是否需要 `min-width: 0`，不要机械加入。mixin 定义应保留在共同祖先内、普通 CSS 属性之后、嵌套选择器之前；调用也应放在消费者的普通 CSS 属性之后，并保留原 DOM 路径。

**验收方式：**在明确限制宽度的容器内放入长文本，确认标题、摘要均显示省略号，短文本仍正常显示。仅通过预处理器编译不能完成此项验收。

## 边界说明建议

以下两项不计入已确认功能缺陷；现有示例在满足各自 DOM 前提时可以成立。

### S1 · P3：为 deep 示例补充“同一根节点”分支

位置：[deep-selector-examples.md](../css-code-rules/references/deep-selector-examples.md)，第 9、20–36 行；关联入口规则 5。

现有示例没有展示模板。按其写法，Less 与 Vue scoped 编译后的关键选择器为：

```css
.result-table[data-v-audit] .arco-table .arco-table-container {
  width: 100%;
}
```

它要求 `.arco-table` 是业务根的后代。如果业务类通过组件属性落在组件库根上，实际 DOM 是同一个元素同时持有 `result-table` 和 `arco-table`，该选择器便无法匹配。

参考文档已经允许在不存在合适的根下共享祖先时使用多个 deep 分支，所以这里不能认定规则必然错误。缺少的是正例的 DOM 前提，以及同根场景的决策示例。

**建议：**给现有正例补上业务包装节点与组件库节点的关系；另补一个同根示例，说明从该根直接 deep 到内部目标。避免读者为套用示例增加无必要的包装节点。

### S2 · P3：区分自有 Teleport 节点与组件库创建的弹层

位置：[style-scope-and-extraction-examples.md](../css-code-rules/references/style-scope-and-extraction-examples.md)，第 7、22、44–54 行。

示例直接建议给 teleported 内容使用 unscoped 样式，容易让读者把“离开组件原有 DOM 根”理解为“丢失 Vue scope 标记”。对于同一 SFC 自己渲染的 Teleport 节点，这个推断并不成立。

最小 SSR 编译输入：

```html
<Teleport to="body"><div class="cand-filter-popper">text</div></Teleport>
```

启用 scoped 编译后，生成的 Teleport 输出仍包含：

```html
<div class="cand-filter-popper" data-v-audit>text</div>
```

此时原根的后代选择器可能因为 DOM 迁移而失效，但单独的 scoped 弹层根仍有适用空间。组件库内部创建的弹层则需检查实际节点、scope 标记及库提供的定制入口。

**建议：**说明是否需要 unscoped 应取决于实际样式匹配条件；保留业务限定根要求，补充自有 Teleport 可以使用独立 scoped 根的分支。上述验证只覆盖编译行为，未执行客户端挂载验收。
