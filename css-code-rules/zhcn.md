# CSS 代码规则

本文是 [SKILL.md](SKILL.md) 的中文翻译，便于阅读和对照。

适用范围：编写、修改、重构、审查、调试或补全 CSS、Less、Sass、SCSS 或 Vue 样式块时，必须遵守本技能规定的样式架构、命名、嵌套、布局、作用域、复用和兼容性标准。

处理上述样式代码时，应用下列所有相关规则。保留项目有意采用的不同约定，改动限于用户请求的范围。

详细示例按本文的主要章节分类存放在 `references/` 中。编写或审查相关模式前，只阅读对应的参考文件。示例用于解释规则，不能覆盖仓库已建立的约定。

## 工作流程

1. 修改或审查样式前，阅读仓库说明，检查受影响的标记结构、所属组件、邻近样式、全局重置与设计变量、预处理器、PostCSS 设置、目标浏览器配置，以及格式化或 lint 脚本。布局与兼容性决策必须以实际渲染的归属结构和项目配置为依据。

2. 确定任务涉及的规则章节，操作前阅读对应示例。Vue 样式块同时遵守 `vue-code-rules`；同一次单文件组件修改涉及 TypeScript 时，还需遵守 `ts-code-rules`。

3. 选择器、覆盖、提取和清理都应限制在请求涉及的归属边界内。如果本地约定与规则冲突，遵守更高优先级的指令和仓库有意采用的约束。不要借样式任务重构无关标记结构或全局样式。

4. 修改后，逐项对照相关章节检查差异。有预览或现成视觉测试时，验证受影响的视觉状态。运行最小范围的定向格式化、样式 lint、构建或相关测试，不重写无关文件。无法进行视觉或自动验证时应说明限制，不能只凭语法有效就认定正确。

## 作用域与文件组织

确定样式语言、Vue 作用域、提取后的文件布局、归属或覆盖位置时，阅读[作用域与文件组织示例](references/scope-and-file-organization-examples.md)。

1. 保留项目已选择的样式语言。不要仅为统一而在 CSS、Less、Sass 或 SCSS 之间迁移。在用户的 Vue 项目中，新建组件样式使用 Less，除非目标仓库有意采用其他方案。

2. 普通 Vue 组件样式使用 `<style lang="less" scoped>`，属性顺序保持如此。仅真正的全局规则或渲染在组件根节点之外的内容，才使用不带 scoped 的样式块。

3. 提取后的组件样式放在入口文件旁边。只有一个样式文件时，使用与 `index.vue` 同级的 `index.less`；仅当 scoped 和非 scoped 样式确实需要隔离时，才创建 `style/` 目录。样式块达到 200 行时，提取到同级文件，再通过组件的 scoped 样式块导入。

4. 一个组件的所有样式保存在同一份样式表中，不要按视觉区域或功能拆分。只有 CSS 作用域本身要求隔离时，才可以拆成多个样式文件。

5. 应用级重置、主题变量、组件库覆盖和工具样式，放在仓库既有的 `src/styles` 文件中。特定组件对 Element Plus 或 Vant 的覆盖，应通过 `:deep` 限制在所属组件的根节点范围内。

## 命名与嵌套

确定业务根类、BEM 命名、归属嵌套、直接子级边界、深度选择器、伪类或业务状态时，阅读[命名与嵌套示例](references/naming-and-nesting-examples.md)。

1. 每个组件都要有含义明确的业务根类，其所属选择器都放在该根类之下。通过 Teleport 渲染的内容位于组件树外，可以使用独立且包含完整业务限定含义的根类。

2. 遵循 BEM 语义，但各部分之间统一使用单连字符：`block-element-modifier`。项目自有类名不得引入 `__` 或 `--`。组件库自有选择器保留库本身的命名。

3. 每个类名都应表达组件、元素、状态或业务含义，避免模糊名称和任意后缀链。

4. 禁止过长类名。先删除冗余归属词、重复业务术语、视觉描述和无必要的后缀，同时保留识别组件、元素或状态所需的含义。不要仅因为名称映射了每层 DOM 祖先，就保留冗长名称。

5. 删除冗余措辞后，类名仍难以保持合理长度时，可用一致且易理解的字符缩写缩短重复业务片段。优先采用仓库或功能术语表中已有的缩写，在整个归属子树中，同一术语使用同一缩写。不得仅为减少字符数而创造含糊、不透明、随意拼接或任意的字母序列。

6. Less/Sass 中，每个子级或后代选择器必须按照 DOM 和组件归属层级，嵌套在直接所属父级的选择器内部。此项强制执行：不得把子级选择器写成独立或游离于根级的规则，也不得仅为降低嵌套深度而扁平化。只有真正的样式表根规则、全局规则和独立渲染的 Teleport 根规则可以位于顶层。嵌套时保留完整类名，不要通过字符串拼接生成难以理解的名称。不要滥用直接子级选择器：只有确需限定直接子级、以避免误匹配后代，而且该边界是稳定且有意义的 DOM 契约时，才使用 `& >`。不要仅因为元素当前恰好是直接子级就使用它，其余情况使用普通嵌套后代选择器。确需直接子级选择器时，必须以 `& >` 开头，不得使用裸 `>` 开始嵌套选择器。

7. Vue scoped 样式中的每个深度选择器，都必须通过 `&:deep(...)` 直接指定目标，不得调用没有选择器参数的 `:deep`。多条深度规则属于同一个组件库子树时，将 `&:deep(...)` 放在最近且适当的共同父级，将后代嵌套在其内部，不要在后代上重复 `:deep`。后代选择器、组合选择器、伪类和伪元素都遵守这一规则：在共同的 deep 块内，嵌套到各自所属的选择器之下。只有目标在组件根节点以下没有合适的共同库内父级，也就是仅共享组件根节点时，才允许多个同级 `&:deep(...)` 块。能够合并到一个共同 deep 父级时，不要编写一长串同级块。不得把业务根类加 `:deep()` 扁平化为独立选择器，也不要散落编写逗号分隔的 deep 规则。

8. 伪类嵌套在所属选择器中。业务状态使用与所属选择器连写的显式完整类名表示，子级变化保留在对应状态块内。

## 设计、布局与复用

确定设计变量使用、布局方式、不同终端的表现、单位、组件库定制、冗余删除或可复用抽象时，阅读[设计、布局与复用示例](references/design-layout-and-reuse-examples.md)。

1. 颜色、间距、圆角、字体和状态复用仓库的设计变量、工具及已有语义值，避免近似重复的字面量。仅当重复内容使归属更清楚时，使用 Less/Sass 变量、mixin 和循环。

2. 避免使用 CSS Grid。布局使用 Flexbox 配合 `gap`，除非 Flexbox 无法正确表达真实的二维对齐需求；只有能够证明确有必要时，才将 Grid 作为最后手段。占据剩余空间的区域使用 `flex: 1`，固定尺寸区域使用 `flex-shrink: 0`。凡 flex 收缩或省略号依赖溢出裁剪的位置，都应添加 `overflow: hidden`。

3. 仓库已有独立的桌面与移动端页面、组件目录时，保持这种区分。实现已经按终端目录拆分的，不要再在组件内部添加媒体查询分支。

4. 使用仓库配置的单位策略。在这些项目中，普通间距、尺寸和字体大小使用 `px`，由已配置的 PostCSS 转换生成移动端 `vw`。只有数值确实表达视口关系时，才使用视口单位。

5. 局部定制优先使用组件库文档提供的 CSS 自定义属性。作用域内的变量或普通嵌套选择器已足够时，不要提高选择器优先级或使用 `!important`。

6. `box-sizing: border-box` 只在既有全局或顶层规则中定义一次，不得在组件中重复。固定尺寸已确定最小尺寸时，不要再重复对应的最小尺寸或等价的固定 flex basis。删除在元素实际格式化上下文中没有效果的声明。只有出现真实重复后，才将重复布局、截断、过渡或动画模式提取为职责集中的 Less/Sass mixin、变量或既有工具。不要重复声明全局重置或浏览器默认已提供的值。只有为实现具体且可观察的布局或排版结果所必需时，才保留原本冗余的声明。

## 声明与兼容性规范

确定注释、空行、声明顺序、合并、浏览器支持、回退方案或最终格式检查时，阅读[声明与兼容性示例](references/declaration-and-compatibility-examples.md)。

1. CSS、Less、Sass、SCSS 和 Vue `<style>` 块中应避免注释。不要添加常规分区标题、选择器说明、声明解释、注释掉的代码或只是复述样式表的注释。只有不直观的兼容性处理、外部库限制或临时例外无法通过命名和结构清楚表达时，才添加注释。例外注释应简洁，解释必要原因，并使用中文，除非准确外部术语或项目强制约定要求其他语言。

2. CSS、Less、Sass、SCSS 或 Vue `<style>` 块中不得保留无意义空行。只有确实分隔独立选择器组或逻辑区域时，才允许一个空行。禁止连续空行、文件开头或结尾空行、选择器或 at-rule 块边界内侧空行，以及相关声明与嵌套选择器之间的空行。真正独立的组之间最多保留一个有意设置的空行，删除不能改善结构可读性的空行。

3. 选择器内部的声明顺序为：定位与溢出；交互；尺寸（先高度后宽度）；外边距与内边距；背景、边框、圆角及效果；字体与颜色；显示与布局；动画与过渡。嵌套选择器放在声明之后。

4. 不要重复编写内边距、边框、布局或状态代码块。将相关子级选择器合并到所属父级之下，仅在真实复用时提取重复模式。

5. 不要引入已知存在目标浏览器兼容性问题的 CSS API、选择器、单位或属性。添加新特性前，确认支持情况或使用仓库认可的回退方案。

6. 仅用仓库格式化工具处理本次修改的样式文件，再对照结构规则和本地既有约定检查结果。
